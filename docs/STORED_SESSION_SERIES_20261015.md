## Выявленный пробел и исправление

В main есть внутреннее чтение, но нет отдельной команды MCP для выдачи сохранённого
ряда между сессиями. Добавлена `history.stored_series` — тонкий диагностический
интерфейс над тем же load_exact, без изменения существующих sync/read/Forecast.
Команда объявлена только читающей, повторяемой и не обращающейся наружу.

Параметры: `secid`, `timeframe` (D1/H1/M15), `from_date`, `till_date` (YYYY-MM-DD).
Пример:

```json
{"secid":"SBER","timeframe":"H1","from_date":"2026-10-09","till_date":"2026-10-12"}
```

Для фьючерсов указывать точный контракт, например SiZ6/GDZ6; Si/BR/GOLD
не принимаются. Метаданные инструмента берутся из существующего хранилища.
Дата фильтра — записанная календарная дата begin, не аттестованная торговая дата.
Максимум 367 календарных дат включительно, не более 50 000 строк.

## Правила соединения

1. Отдельно для каждого точного инструмента и каждого периода.
2. Исходные цены, объёмы, begin/end, available_at, observed_at, revision,
   source и completed возвращаются без преобразования из существующего read.
3. Разрыв цены между сессиями остаётся. Выходные, ночь, клиринг и отсутствующие
   интервалы не заполняются нулевыми, перенесёнными или выдуманными свечами.
4. Неполные свечи можно увидеть в диагностике с исходным флагом. Число полных и
   неполных указано отдельно; это не разрешение использовать их в прогнозе.
5. Повторные одинаковые порции не создают дополнительные ключи в хранилище.
   Это не устраняет отдельные известные дефекты выбора версий старого read:
   конфликт цены/версии и forming→final остаются в существующей очереди исправлений.
6. Повтор времени, нарушенный порядок, перекрытие интервалов, чужая идентичность,
   неверный диапазон или превышение пределов закрывают выдачу.
7. Неизвестное время первого получения и торговый календарь остаются
   UNVERIFIED. Чтение не выдаёт прогноз и не меняет ранее выпущенные записи.
8. Эта команда не делает M1→M15 или M15→H1/D1. Сборка таймфрейма из минут,
   торговые даты через полночь и независимая проверка расписания — отдельные правила.

## Проверка и установка

Результаты проверок фиксируются в PR и общей карте. Проверены отдельные порции
пятницы/понедельника, обратный порядок загрузки, повтор порции, сохранение разрыва
100.25→130.75, NULL, forming, точный контракт, пустой период, неверные/перекрытые
интервалы и ограничения. Сквозная проверка запускает настоящий отдельный MCP
процесс, делает initialize/tools/list/tools/call для D1/H1/M15 и негативный вызов.
Внешние HTTP и соединения запрещены; Windows loopback для asyncio разрешён.

Это проверка изолированного MCP на синтетике. Не REAL MOEX PASS и не HOME PASS.
Первый стендовый сбой был из-за запрета внутреннего socketpair Windows; второй —
из-за desktop.ini внутри JSON-схем тестового окружения на Drive, третий — из-за
старых имён полей SDK в тестовом клиенте. Рабочие цены и механизм чтения для их
устранения не менялись. Схемы проверены из локальной копии без desktop.ini;
проверка результата MCP не отключалась.

Для установки нужен отдельный контрольный выбор версии, объединение и обновление
только сервера Биржи; затем проверка наличия команды через защищённый MCP-контур.
До этого в памятках и карте указывать «код/изолированный MCP проверен;
рабочая установка не обновлена». Основная ветка, HOME и рабочие базы не менялись.

## Обязательный вход для нового исполнителя

В корне GitHub размещён AGENTS.md с обязательной навигацией, автономностью и
правилами загрузки/хранения. Команда history.session_rules возвращает те же
операционные ограничения, адреса шести канонических таблиц, роли листов и
installed_source_sha работающей установки. Команда не читает ключи и не
предоставляет доступ сама по себе. Объявление Google-адресов не означает
установленного зеркального экспортёра — это проверяется отдельно.

Порядок: tools/list → history.session_rules → разрешение инструмента/контракта
→ history.coverage → разрешённый history.sync по недостающим порциям
→ history.stored_series по точному SECID → проверка качества/календаря/допуска
→ фактически разрешённая выгрузка и обратное чтение → запись результата.
Не задавать вопрос на каждую страницу, сессию или обычную проверку. Если после
2–3 попыток подход не работает, сообщить конкретный блокер и необходимое действие.
Существующее разрешение пользователя действует в пределах задачи.

Первоначальные результаты и фраза об отсутствии установки выше — датированный
снимок. Фактическую установленную версию смотреть через history.session_rules,
текущую приёмку — в общей Карте проекта. Это предотвращает повторные вопросы по
устаревшему снимку документа после разрешённой установки.
