# G2 — безопасный переход к запрету неподтверждённых методов выпуска прогнозов

**Исследовательский Draft. Не установлен в HOME и не включён по умолчанию.**

## Почему делаем

16.10.2026 владелец принял решение не развивать эвристические v0.4/v0.6 как рабочие прогнозы; они остаются историей испытаний. Старые Forecast Records сохраняются неизменными, Outcome Journal остаётся append-only. Свечной Volume Profile не допускается как независимый фактор направления, Control, Route.

## Где проверяется допуск

Единый реестр статусов: `src/birzha/application/method_registry.py` (Draft #255). Новый `forecast_issuance_policy.py` читает точный список `approved_predictive_methods`. По состоянию на 16.10 этот список **пуст**: ни одна модель не прошла независимую прогностическую приёмку.

- `BIRZHA_FORECAST_ISSUANCE_POLICY=legacy_compat`: историческое поведение разрешает старую формулу, **но это не признание её точности**. Это настройка по умолчанию, исключающая неожиданное изменение работающего HOME при получении нового кода без отдельного разрешения.
- `BIRZHA_FORECAST_ISSUANCE_POLICY=approved_only`: **новый `forecast.create` запрещён**, `forecast.build` запрещён как оперативный прогноз, `analysis.run_core` прекращает работу **до обновления истории**. MCP отвечает `BLOCKED / METHOD_NOT_APPROVED_FOR_NEW_FORECAST`. `ForecastJournalService.create_and_save` отказывает до построения Snapshot и до journal.append, даже если вызван не через MCP.
- `forecast.get` / `forecast.list` продолжают работать; `outcome.evaluate` остаётся допустим для уже зафиксированных старых прогнозов; исследовательские тесты `validation.*` не становятся автоматически допущенными прогнозами.

## Риски и доказательства

- В MAIN, HOME и текущем runtime НИЧЕГО не выключено: Draft #256 ещё требуется независимо проверить и получить отдельное разрешение на merge/deploy + изменение environment.
- Прежняя эвристика `build_forecast_from_snapshot()` не удаляется: она нужна для воспроизведения оригинальных Forecast/Outcome, но нельзя принимать её результат за допущенный operational прогноз.
- Future model admission — новая утверждённая версия, методологические доказательства, отдельный прогнозный допуск, без задним числом изменённых результатов.
- `approved_only` означает отсутствие новых прогнозов до появления действительно утверждённой модели. Это **преднамеренное** поведение, и его включение требует согласованного перехода.
- В обычном `legacy_compat` создание старых прогнозов остаётся возможным; только документация/реестр сами по себе ничего не блокируют. Не объявлять отказ работающим до подтверждённого режима на HOME.
- Нельзя менять production DB, удалять старые записи, считать CI статистическим доказательством, запускать торговлю, вводить реальные секреты в GitHub.
