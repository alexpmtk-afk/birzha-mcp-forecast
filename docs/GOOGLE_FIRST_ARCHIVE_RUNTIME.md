# Google-first архив: контракт, установка и приёмка

Решение владельца 31.10.2026: Google Sheets — постоянный архив свечей, показателей и статусов; M1 — месячный ZIP на Google Drive с каталогом в M1_SOURCE_INDEX. Локальные DuckDB и резервирование DuckDB не являются предпосылкой внедрения этого сборщика. Существующие базы не удаляются. Forecast/Outcome сохраняют свой отдельный прежний контур.

## Версии и источники правил
Проверены оригиналы workspace AGENTS.md, docs/DATA_TABLE_FORMAT.md, docs/DATA_UPDATE_POLICY.md и живой RI STORAGE_RULES A1:B60. На момент чтения RI книга содержит STORAGE_RULES, M1_SOURCE_INDEX, QUALITY_AUDIT, SYNC_STATUS; README_STATUS отсутствует намеренно и никогда не восстанавливается.
Проверены metadata и D1!A1:AB1 шести канонических книг: одинаковые 28 имён полей. Идентификаторы книг берутся только из GoogleSheetsBridge.target_for_symbol и INSTRUMENT_FOLDER_IDS, без поиска по имени и создания замены.
Зависимость: открытый PR #289, 6baa060e20ff1edc069b84e3f2cd90b3574cd00a (ветка feature/m1-month-source-v1-20261031). Используются его проверка ZIP, проверка минут, дедупликация и детерминированная упаковка; альтернативный M1 формат не создаётся. Новый адаптер передаёт байты из памяти, локальный publish_month не вызывается. Стандарт #287 учитывается по действующему прямому решению владельца и STORAGE_RULES; его объединение не предполагается.
PR #290 пересмотрен: сохранены идея предварительной проверки версии/готовности и системная блокировка. Его путь history.sync -> DuckDB -> mirror.sync, локальные request/PID-файлы и требование резервирования DuckDB не перенесены. Это замена сценария, а не совместимый запуск старой зеркальной цепочки.

## Отдельный runtime
Команда: python -m birzha.mcp.archive_server. По умолчанию отдельный loopback порт 18085. Процесс не импортирует duckdb/ydb и не создаёт историческое хранилище, Forecast/Outcome или локальные журналы. Старый сервер Forecast 18082 не заменяется и этим кодом не перезапускается.
Обязательные настройки: BIRZHA_ARCHIVE_GOOGLE_CREDENTIALS_PATH (явный существующий защищённый credential-файл), BIRZHA_MCP_BEARER_TOKEN (из защищённой среды), полный BIRZHA_SOURCE_SHA. Запись требует BIRZHA_ARCHIVE_SOLE_WRITER=true, только после реального подтверждения единственного писателя. Одновременно включённое legacy/native mirror запрещено в архивном runtime.
Google scopes нового режима: spreadsheets и drive для чтения существующих ZIP, сохранения старой ревизии и обновления того же объекта. Это отличается от прежнего mirror с drive.metadata.readonly. Старый scope по умолчанию не изменён. Уже выданный OAuth refresh token не расширяет полномочия автоматически; отсутствие нужных прав — ошибка, не разрешение искать другой ключ. Service account должен иметь необходимые права только на согласованные книги/папки. Значения ключей не логируются.
Стартовый скрипт scripts/start_home_google_archive.ps1 принимает явный путь credential, проверяет отдельный порт и установленный SHA. CheckOnly проверяет конфигурацию без старта. OwnerConfirmedSoleWriter требуется отдельно для записи; без него сервер только планирует/читает. Скрипт не создаёт задачу Windows и не меняет HOME.

## MCP контракт нового режима
- archive.status: runtime GOOGLE_FIRST, local_candle_store=false, local_journal=false, source_sha, sole_writer и шесть инструментов.
- archive.coverage(symbol,timeframes): читает Google, возвращает даты, количество и точные контракты по каждому периоду; не заявляет полноту сессий по количеству строк.
- archive.collect(symbol,timeframe,day,exact_secid?,dry_run=true): один законченный гражданский день. Проверяет Google и журнал, определяет исторический контракт по прежнему причинному T-1 resolver, при необходимости загружает ровно этот день/период. exact_secid — проверка выбора, а не обход T-1. RI — фьючерс, RTSI исключён; GOLD — GD..., не акция GOLD.
- archive.sync / archive.update: одинаковая ограниченная координация нового сбора по символу, диапазону максимум три дня и D1/H1/M15. Это НЕ прежний RI-only расчёт непрерывных исследовательских координат. Контракт определяется archive.status перед запуском; клиент старого endpoint нельзя направлять сюда молча.
Preview по умолчанию не вызывает MOEX и не пишет статусы. Применение требует отдельного флага. Только принятые/переиспользованные окна дают общий PASS; неизвестное покрытие возвращается отдельно, не маскируется успехом.

## Поиск пропуска и сохранность
Сначала читаются исходный лист и имена/ключи/значения, проверяются дубли и единицы представления времени. Существующий D1/H1 без полной квитанции сохраняется и возвращается EXISTING_UNVERIFIED_NO_FETCH; его повторное скачивание не разрешается ради формальной полноты. Для M15 сначала читается облачный M1 ZIP; из него восстанавливаются наблюдаемые недостающие интервалы, а совпавшие старые строки сохраняют прежние ключи и метаданные.
Пустое окно допускает один ограниченный source call через прежний общий MOEX governor. До него в SYNC_STATUS сохраняется FETCHING. Тайм-аут с неизвестным результатом не повторяет MOEX вслепую: SOURCE_RESULT_UNKNOWN_REVIEW_REQUIRED. Это явный предел автоматического восстановления для D1/H1, не постоянный локальный журнал. После получения источник делится на небольшие PREPARED-фрагменты в существующем SYNC_STATUS; никаких новых служебных вкладок.
CanonicalMirrorPublisher дописывает только отсутствующие ключи, сверяет текущий лист перед порцией и читает его обратно. Потеря ответа после commit возобновляется по облачным PREPARED-строкам, без MOEX. Завершённая квитанция содержит хеш Google-строк; повтор проверяет его без скачивания. При внешнем изменении/конфликте цен — остановка. Пустой ответ не превращается в нулевую свечу и не аттестует календарь. Он даёт SOURCE_NOT_AVAILABLE, облачную отметку времени наблюдения и часовую паузу перед повторной проверкой всё ещё пустого окна; отсутствие ответа не фиксируется как вечная завершённость архива.
Первый backfill не должен быть массовым: максимум три дня на запрос, бюджет 1..12 окон. Сценарий выбирает начало по последним датам Google; для пустого архива требует явно заданное начало и для отставания >31 дней возвращает отдельное поручение ограниченного backfill. Полнота старых внутренних пропусков без календарного/источникового доказательства не выводится из сетки.

## M1 и M15
M15 строится прежним MoexIssClient._aggregate_m15 из наблюдаемых M1. Пропущенные минуты не создаются; разреженные M15 сохраняют is_complete=false и число наблюдений. Нестандартные H1 также не объявляются полными. Незавершённые текущие дни отклоняются; исторические available_at, first_seen, trade_session_date и session_id не выдумываются.
Перед M1 source call проверяются существующие 01_M1_SOURCE и M1_SOURCE_INDEX. Один объект symbol_SECID_YYYY-MM_SOURCE_M1_OHLCV.zip на контракт/месяц. Проверяются внешний SHA, внутренняя контрольная сумма, идентичность, минуты, OHLCV, конфликты и месяц; работа только в памяти.
При расширении месяца старые минуты должны совпасть. У того же Drive file ID сохраняется старая ревизия keepForever, затем загружается новая; всегда GET и побайтная проверка ZIP, затем обновление существующей строки каталога с обратным чтением. Неизменённый набор не загружается повторно. При потерянном ответе/расхождении индекса — сверка облачного объекта, без создания второго канонического ZIP. Каталог без файла или дубли объектов блокируют работу.
На момент живой проверки M1_SOURCE_INDEX и STORAGE_RULES имеются только у RI. Поэтому реальная M15-установка остальных пяти инструментов блокируется отсутствием утверждённого каталога/источника; этот PR не создаёт запрещённые листы. D1/H1 от M1_SOURCE_INDEX не зависят. Кодовый маршрут M15 для шести символов проверен на изолированных транспортных заменителях.

## Показатели и аудит
Существующие INDICATORS и их формулы/массивы не переписываются. Архивный сборщик не пересчитывает заново Purnov/continuous/model-specific показатели; штатное Google автозаполнение сохраняется. Ответ явно сообщает EXISTING_FORMULAS_PRESERVED_NOT_RECOMPUTED. Расширение полноты показателей проверяется отдельно после фактической записи; наличие свечи не означает готовность всех индикаторов.
Прогресс/контракт/квитанции/ошибки пишутся в существующий SYNC_STATUS, события с фиксированными кодами — в QUALITY_AUDIT. Схема QUALITY_AUDIT проверяется по именам 14 полей; произвольные тексты upstream исключений и payload не сохраняются в аудит. Копии источника PREPARED содержат только OHLCV/явные ограничения в закрытой книге. Локальный служебный журнал не является зависимостью.
При отказе самого Google сохранить ошибку в недоступной книге невозможно: MCP возвращает BLOCKED; не создаётся параллельный локальный архив. Следующий запуск читает состояние и сверяет его, не повторяет запись вслепую. Между несколькими процессами/компьютерами Google не даёт CAS для этой цепочки: нужен подтверждённый единственный писатель и отсутствие старого обновляющего цикла.

## Автоматический запуск
scripts/run_home_history_and_mirror.ps1 теперь вызывает только scripts/run_google_archive_cycle.py, без history.sync/mirror.sync и локальных request/PID файлов. Проверенный Enter-RefreshLease использует Global mutex. Без Apply клиент только планирует; по умолчанию D1 для всех шести символов. H1/M15 включаются явно после проверки облачного каталога и схем. Клиент принимает только loopback /mcp, сверяет archive.status/source_sha и начинает с последних дат Google. Произвольный endpoint, старый runtime и отсутствие авторизации отклоняются.
При установке нельзя запускать старый bootstrap или просто обновить checkout, оставив зарегистрированный внешний run-history-refresh.ps1. В согласованное окно остановить именно старый часовой писатель, подтвердить отсутствие конкурентов; сохранить его конфигурацию локально. Разместить новую точку запуска и обновить её ссылку отдельно, не включать Apply молча. Учесть, что относительные пути нового сценария рассчитаны на запуск из repo/scripts; прямое копирование его в старую внешнюю папку не является корректной установкой.

## Приёмка и откат
1. Независимо просмотреть зависимость #289 и этот PR; проверить полный CI точного HEAD. Объединение и установка требуют отдельного решения владельца.
2. До установки оставить текущие DuckDB без изменений. Их резерв не нужен этому отдельному процессу, он к ним не подключается. Проверить креденциальные права, единственного писателя, актуальные источники запусков и выбранный SHA.
3. Поднять только новый отдельный archive endpoint без Apply, проверить auth/status/tools. Старый Forecast/Outcome не переключать на новые архивы автоматически.
4. Пробно прочитать ровно нужную книгу/лист/ключи, выбрать один отсутствующий D1 и правильный исторический контракт. После разрешения применить одно окно; прочитать старые/новые строки, ключи, OHLCV, статусы и формулы индикаторов обратно. Повтор — без нового MOEX и без новых свечных строк. По очереди повторить для остальных пяти инструментов.
5. Затем принять плановый цикл D1. H1/M15 — отдельно после готовности M1_SOURCE_INDEX/Drive источников. Не заявлять REAL MOEX/HOME PASS по заменителям.
6. При откате остановить только новый цикл/архивный процесс по отдельному разрешению. Google-строки не удалять и не откатывать из старой DuckDB: сохранить статусы, сверить ключи/источник и подготовить ограниченное исправление. Forecast/Outcome и старые базы остаются как были. Возвращение старого писателя требует отдельной оценки его RTSI-маршрута и не выполняется автоматически.

## Проверки подготовленной редакции
Полный локальный набор: 638 PASS на Windows/Python 3.13; repository_preflight PASS; public_repo_security PASS, 0 находок; оба PowerShell сценария разобраны синтаксически. В новом наборе проверены D1/H1/M15 для всех шести символов, неизменность формул/старых строк, повтор без source call, потеря write acknowledgement, тайм-аут источника, временно пустой ответ с паузой, явный неправильный контракт при повторе, семантические дубли ключей, неверный день до загрузки ZIP, версии ZIP/каталога, контрольные суммы, реальный MCP initialize/call/auth на ASGI заменителе и импорт runtime при запрещённых duckdb/ydb. Реальные исходники MOEX и настоящие Google-данные в этих тестах не запрашивались/не изменялись; отдельные read-only чтения схем/правил перечислены выше.
Рабочие HOME, DuckDB, автозапуск и настоящие источники M1 не изменялись. Локальные тестовые данные искусственные. CODE PASS не означает реальное включение источника, готовность всех показателей, наличие M1_SOURCE_INDEX в пяти остальных книгах или HOME PASS.
