## Практическое продолжение — парное исследование

1. **До наблюдения будущего** закрепить точный код каждой версии, formula SHA, calendar/SECID, время T0, правила построения входа, горизонты, основания `ABSTAIN`, список новых дат и источники raw OHLCV. Нельзя выбирать только «удачные» исторические точки или менять формулу после результатов.
2. Разные версии должны получать одинаковые доступные D1/H1/M15 для одного exact SECID, одинаковый момент T0 и один набор горизонтов. В архиве с ненадёжным `completed` или `first_seen` сохранять `RECONSTRUCTED_RESEARCH_ONLY`, не выдавать за прошлые реальные прогнозы.
3. Для каждого наблюдения две **разные** записи исследования (version_id + source_SHA + input_SHA + decision_status + direction + predicted_move_pct для H5/H10/H20). Даже при отказе обе версии имеют запись со статусом и причиной, а не фиктивное нулевое направление. Прогнозные артефакты — только изолированная папка/эксперимент; никакой записи в действующий `FORECAST_JOURNAL_TEST` или DuckDB задним числом.
4. Сравнивать на **одинаковых случаях** с двумя ориентирами: `P_flat=P0`, простая инерция `r5=P0/C_(t-5)-1`, `P_momentum(H)=P0*(1+r5*H/5)`. Направление сравнивать только когда версия действительно дала UP/DOWN; отдельно публиковать случаи, где дала NEUTRAL/ABSTAIN.
5. Через **5, 10, 20 реально закрытых торговых сессий** сохранить price outcome и реальную дату (если срок не созрел — PENDING, если контракт истёк — ROLLOVER_UNRESOLVED, если нет источника — MISSING_OUTCOME); не пересчитывать задним числом исходный Forecast. Метрики: число всех наблюдений, % с направлением, правильность направления, MAE величины движения на одинаковой парной выборке, относительные ошибки против flat/инерции, разница отказов и ошибки по каждому рынку.
6. Первый пилот — порядка 10–20 **новых** дат по шести рынкам, не подгонять параметры к прежним 17 исходам. Если действующий [пилот структуры G2](G2_FIRST_FORECAST_STRUCTURE_PILOT_PREREG_20261017.md) использует иные правила, сравнение вести как отдельный research trial с отдельным ID, не переписывать тот зафиксированный протокол.

## Следующее исполняемое действие и доказательства

- Технический smoke: существующий `main` и исследовательский `codex/g2-baseline-decision-contract-20261010` должны отдельно успешно пройти свои тесты, проверить `ENGINE_VERSION/FULL_WINDOWS_ENGINE_VERSION` и невозможность молча подменить одну версию другой. GitHub CI — **техническая проверка, не прогнозная точность**.
- Подтверждение установки/данных HOME не получено; запуск реального перспективного сбора требует доступа к независимой первичной фиксации времени и отдельного согласованного непроизводственного пути.
- PR #255 изменяет **статусы и справочники**, не меняет саму старую формулу, не сливает branch v0.6, не активирует автоматическую торговлю.
- PR #256 содержит опциональную политику `approved_only` для **операционного** выпуска. Исследовательское тестирование двух версий от этого статуса не запрещено. Внешний `forecast.create` не получать новый допуск только из-за реестра.

## Следующее заранее ограниченное парное исследование (подготовлено, не запущено)

Чтобы не создавать ещё одну произвольную выборку, предлагаем использовать **те же 12 будущих слотов по 13:10 МСК**, которые уже перечислены для отдельного наблюдательного пилота Market Structure в Draft #259: **20, 22, 26, 28, 30 октября и 3, 5, 9, 11, 13, 17, 19 ноября 2026 года**. Это до 72 рынок×дата для 6 рынков, каждое наблюдение должно содержать две независимые версии v0.4 и v0.6 либо явный отказ. Пилот v0.4/v0.6 имеет **отдельный идентификатор G2_V04_V06_PAIR_V1**, не меняет замороженную модель #259.

В каждом слоте — один точный SECID (для фьючерсов отдельное заранее определённое правило выбора и подтверждённый срок обращения на все нужные горизонты), подтверждённый календарь D1/H1/M15 и фактические first receipt/source SHA **до** 13:10. При отсутствии входов — сохранять отказ, **не переносить дату**. Числовые и направленные результаты для H5/H10/H20 фиксировать до будущих исходов в новом непроизводственном неизменяемом файле с SHA и двумя точными engine-version/ref; отсутствующие данные не подменять. После созревания исходов публиковать как coverage, так и MAE/точность направления для одинаковых пар; сравнивать с неизменной ценой и пятидневной инерцией. Результат 10–12 дат — только проверка процесса, а не основание утверждать статистическую точность.

**Зависимость перед стартом:** доступ к авторизованному непроизводственному первичному сборщику и хранилищу, где запись времени получения действительно подтверждена; точный календарь и контракты. Ни этот Draft PR, ни GitHub Actions не означают запуск ежедневного наблюдения на HOME. Отдельное разрешение необходимо для любого рабочего развёртывания. Операционную политику `approved_only` на HOME менять не требуется для изолированного испытания.
