# Единый архив инструмента: реальные команды MCP

Редакция 31.10.2026. Основное хранилище этого контура — закреплённая Google Таблица инструмента. Серверная база может быть источником уже сохранённых наблюдений, но её отсутствие не является основанием скачивать заново заполненную таблицу. Прогнозные модели не владеют своими копиями свечей.

## Что реализовано в этой ветке

1. archive.contract — адрес, роли листов и зарегистрированные общие наборы показателей.
2. archive.contract_plan — существующий исторический выбор точного контракта, включая T−1; не выбор ChatGPT.
3. archive.collect — один точный контракт, один период, не более трёх гражданских дней; сначала читает Google, затем существующий загрузчик.
4. archive.sync — общий проход RI: существующие данные → выбор контракта по предыдущей завершённой торговой дате → недостающие исходники → общие показатели → склейка → запись и обратное чтение.
5. archive.update — сверка существующего архива RI, восстановление M15 из сохранённых M1, общие признаки, порядок и обратное чтение. Общий вход отделён от прогнозной модели. Прежние имена p3_* сохранены в физических столбцах, но другие модели могут читать те же значения.

Ключ источника: инструмент, точный контракт, период, начало бара. Разные контракты остаются разными исходными рядами. Команда archive.sync вызывает существующий расчёт market.continuous_series внутри общего прохода и записывает результат в дополнительные столбцы существующих листов показателей. Исходные цены и объёмы сохраняются.

## Общий проход со склейкой

Предварительный план без скачивания и записи:

    {"name":"archive.sync","arguments":{"symbol":"RI","from_date":"2026-01-05","till_date":"2026-10-29","dry_run":true}}

Применение: те же аргументы, dry_run=false. Для ранее заполненного архива берутся существующие строки. Только полностью отсутствующие окна получают запросы существующего загрузчика. При восстановлении пропуска, влияющего на заполненные показатели, требуется repair_dependent=true; перед этим сохраняется местный резерв.

Один вызов получает не более шести отсутствующих порций «точный контракт / период / гражданский день»; max_source_windows допускает1–12. При исчерпании возвращается PARTIAL_SOURCE_BUDGET и следующий диапазон. Повтор с теми же аргументами продолжает работу по уже записанным строкам. Пустой официальный ответ сохраняется как отсутствие наблюдений, а не нулевой бар; обработка доступных порций продолжается. Заполненное окно без доказательства полного ответа не объявляется полным и не скачивается заново.

Выбор по объёму предыдущей завершённой торговой даты един для D1/H1/M15. Полные строки официальных кандидатов с датами окончания контрактов, ценами закрытия и хешами сохраняются по торговым датам в существующем SYNC_STATUS. Годовой календарь2026 зафиксирован по публикациям MOEX n95564/n96571; дополнительные выходные и праздничные сессии относятся к следующей основной торговой дате. Расхождение наблюдаемого предыдущего дня с календарём останавливает расчёт. Другие годы и инструменты этим календарём не обслуживаются.

Координата — FORWARD_SPREAD: начальный контракт сохраняет исходные цены; при переходе из новых цен вычитается накопленная разница закрытий старого и нового контрактов за предыдущий торговый день. Привязка к началу ряда записывается в SYNC_STATUS и сохраняется при последующем дополнении. Восстановление данных раньше этой привязки блокируется до отдельной миграции. Прогрев до начала запрошенного периода использует дневной журнал решений, а не повторную загрузку внутридневной истории.

В D1_INDICATORS/H1_INDICATORS/M15_INDICATORS добавлены10столбцов после109существующих: версия, координата, признак выбранного контракта, скорректированные открытие/максимум/минимум/закрытие, хеш входа, торговая дата и разница цен при переходе. Исходные109полей, свечи и объёмы не подменяются. Невыбранные контракты остаются в архиве без скорректированной цены. Другие координаты в этих же столбцах автоматически не перезаписываются.

Первоначальное историческое время получения источников неизвестно. Режим RECONSTRUCTED_RESEARCH указан явно; он не заменяет строгий режим market.continuous_series по умолчанию. Завершённость интервала, плотность минут и пригодность для прогноза остаются разными признаками. Эта задача не вводит новый прогнозный алгоритм и не доказывает точность Модели3.

## Примеры реальных инструментов MCP

Аргументы ниже передаются подключённому серверу как tools/call. Это не команды PowerShell.

Узнать закреплённое хранилище:

    {"name":"archive.contract","arguments":{"symbol":"RI"}}

Получить план точных контрактов существующим историческим разрешителем:

    {"name":"archive.contract_plan","arguments":{"symbol":"RI","from_date":"2026-10-26","till_date":"2026-10-29"}}

Предварительно проверить сбор часовых свечей конкретного контракта:

    {"name":"archive.collect","arguments":{"symbol":"RI","exact_secid":"RIZ6","timeframe":"H1","from_date":"2026-10-29","till_date":"2026-10-29","dry_run":true}}

Получить M15 через сохранение M1 и существующее объединение минут:

    {"name":"archive.collect","arguments":{"symbol":"RI","exact_secid":"RIZ6","timeframe":"M15","from_date":"2026-10-29","till_date":"2026-10-29","dry_run":true}}

Применение разрешённого сбора: те же аргументы, dry_run=false. Если окно уже заполнено без доказанной отметки полного ответа, программа возвращает SOURCE_COVERAGE_UNKNOWN и ничего не скачивает. Совпадающая отметка ответа и текущие строки дают ARCHIVE_SOURCE_REUSED без сетевых запросов. Наличие хотя бы одного бара не выдаётся за полноту дня.

Предварительный план показателей и порядка для существующей книги:

    {"name":"archive.update","arguments":{"symbol":"RI","from_date":"2026-01-05","till_date":"2026-10-29","dry_run":true}}

Применение подготовленного плана:

    {"name":"archive.update","arguments":{"symbol":"RI","from_date":"2026-01-05","till_date":"2026-10-29","dry_run":false}}

Если добавление старого бара меняет зависимые заполненные значения, обычный вызов блокируется до явного repair_dependent=true. До исправления сохраняется местный резерв. Неизвестная версия чужой формулы не переписывается.

## Точные места реализации

- src/birzha/mcp/server.py — объявления перечисленных инструментов MCP.
- src/birzha/application/instrument_archive_registry.py — закреплённые книги и общие наборы признаков.
- src/birzha/application/archive_sync.py — общий проход, сохранение журнала переходов, дополнительные координаты и повтор.
- src/birzha/application/forts_calendar_2026.py — опубликованные правила торговых дат2026.
- src/birzha/application/archive_collection.py — проверка Google до запросов, сбор ограниченного окна и приёмка.
- src/birzha/application/model3_archive.py — текущий адаптер книги RI: недостающие строки/поля, зависимости, порядок, резерв, повтор и чтение.
- src/birzha/application/model3_features.py — 119-полевая совместимая схема RI: прежние109полей и10полей непрерывной цены.
- src/birzha/providers/moex_iss.py — действующий запрос D1/H1 и _aggregate_m15; второй сборщик M15 не создавался.
- src/birzha/storage/model3_minute_archive.py — сохранение фактически полученных M1 RI.
- src/birzha/application/model3_minutes.py — проверка архивных сумм и оценочные объёмные признаки.
- src/birzha/storage/native_canonical_sheets.py — единственный Google-писатель, перемещение целых строк и проверяемые точечные изменения.

## Настройка установленного процесса

Используется существующий защищённый native mirror с единственным писателем. Пути BIRZHA_MODEL3_MINUTE_ARCHIVE_DIR и BIRZHA_MODEL3_AUDIT_DIR пока сохраняют прежние имена для совместимости; это пути исходников и резервов, не отдельные хранилища прогнозной модели. Секреты в инструкции и репозиторий не включаются.

Команды не создают облачные книги/листы. Новый инструмент без утверждённого адреса/шаблона блокируется. Настройка и установка работающего сервера — отдельный контролируемый этап.

## Доказательства и границы

- На сохранённых реальных данных RI: 312 D1, 5955 H1, 21737 M15, 232613 M1; сопоставлены 1988284 значения со старым вычислением, расхождений нет. Приватные исходники не включены в Git.
- Изолированный настоящий MCP: initialize → tools/list → archive.contract → archive.update → повтор → mirror.sync(RI).
- Проверены потеря ответа после фактической записи, повтор без дублей, старые пропуски, сохранение исходных строк и подтверждение экстремума только после правых баров.
- Сбор из MOEX и запись в действующую Google-книгу этой версией ещё не выполнялись. Это не приёмка установленного HOME.
- Общий сбор доступен для утверждённых адресов; расчёт зарегистрированного набора из 55 признаков в этой редакции принят только для схемы RI. Наборы других моделей/инструментов не выдумываются.
- Старый адрес RTSI совпадает с нынешней книгой RI: новая команда блокирует RTSI до проверки канонического адреса индекса.
- Внутренние пропуски заполненного окна без доказанного полного ответа не восстанавливаются догадками. Используются сохранённые M1 либо отдельная подтверждённая порция.
- Точная дельта, точное распределение по сделкам, торговый календарь и первоначальная историческая доступность не появляются из OHLCV. Оценки отмечены отдельно. Прогнозы и журнал исходов не меняются.
