# G2 — разбор 12 условий, первопричины и минимальная очередь закрытия

Дата проверки: 10 октября 2026 года. Источник истины — машинный `docs/G2_RELEASE_GATE_20261010.json` + `scripts/g2_release_gate.py` в этой ветке; диагностическая программа `scripts/g2_release_blocker_triage.py` только объясняет его вывод.

## Главный вывод

12 **не означают 12 ошибок CI**. В прежнем принятом состоянии 11 технических/доказательных release-gates имели **1 PASS и 10 OPEN/BLOCKED**, к ним прибавлялись 2 независимых разрешения пользователя на merge и HOME deployment. Новая интеграция #173 временно переводит gate совместимости в PENDING, поэтому до повторных проверок число может стать 13. После доказанного полного PASS оно вернётся к 12 без удаления остальных требований.

Здесь смешаны разные **цели**: (а) допустимость *исследовательского/непроизводственного пилота*, (б) кодовая совместимость, (в) полный Protocol 08 и доказанная предсказательная полезность, (г) операционная безопасность HOME/production. Они не эквивалентны. Эта работа не меняет production release rules и не объявляет пилот production-ready.

## Практический порядок, без холостых повторов

1. **Сейчас:** независимое рассмотрение новейшего #173 и связки с #168/#172/#147, содержательные негативные tests. Именно кодовую совместимость можно получить немедленно; эту строку закрываем только по реальному CI SHA.
2. **Параллельно без production:** проследить весь LIVE issuance route; устранить event-time/receipt-time conflation на staging; подготовить внешний точный SECID календарь и документированную проверку provenance.
3. **Разблокировать HOME read-only:** выяснить штатный допустимый вызов диагностического скрипта без ослабления локальной PowerShell policy; проверить actual branch/SHA/dirty, сервисы и источник; права/рабочие данные не менять.
4. **Для полного релиза:** завершить Protocol 08 и backup/recovery/migration на тестовом контуре; провести независимый code+semantic review.
5. **Только после созревания:** принять настоящие будущие 5/10/20 Outcomes и OOS независимую проверку.
6. **Согласование границы:** выяснить у пользователя, нужен ли *сейчас* только исследовательский prospective pilot или именно production полнофункционального Protocol 08. Возможная новая scope-specific модель должна пройти отдельный контрактный review; изменение release policy не выполняется в этом PR.

## Что запрещено «исправлять» административно

Нельзя отметить старую исходную квитанцию, не существовавшую в архиве, как PASS; нельзя подменять будущие результаты ретроспективными или искусственными; нельзя считать 1252+ тестов заменой независимой семантической экспертизы; нельзя за счёт переименования статусов получить разрешение на merge/deploy. Экспериментальные артефакты цен 09.10 не являются текущими котировками или проверкой точности. Никакого обращения к 2023–24 RESERVED holdout или HOME/production не было.

## Запуск и аудит

```bash
python -m scripts.g2_release_gate --manifest docs/G2_RELEASE_GATE_20261010.json --summary
python -m scripts.g2_release_blocker_triage --manifest docs/G2_RELEASE_GATE_20261010.json --format text
python -m scripts.g2_release_blocker_triage --manifest docs/G2_RELEASE_GATE_20261010.json --format json
```

`--require-release` у основного release-gate должен завершаться ненулевым кодом до реального прохождения всех технических требований и **двух** отдельных разрешений пользователя.
