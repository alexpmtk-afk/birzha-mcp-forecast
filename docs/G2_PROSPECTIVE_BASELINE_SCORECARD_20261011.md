# Сравнение будущего прогноза с простым ориентиром — 11.10.2026

## Назначение и границы

`G2_PROSPECTIVE_ALWAYS_UP_SCORECARD_V3` — отдельная процедура оценки уже
созревших исходов из непроизводственных опытных журналов. Она не создаёт прогнозы
или исходы, не меняет записи, не обращается к бирже и открывает файл базы только
для чтения. Поддерживаются отдельный журнал испытательного соглашения SQLite
`G2_PROSPECTIVE_CAPTURE_PILOT_V1` и однофайловый опытный журнал DuckDB
`G2_ATOMIC_SINGLE_DUCKDB_STAGING_V2`. Оценщик не меняет программу записи в эти базы.

Оценка выполняется отдельно для точного рынка, точного SECID и каждого горизонта
5, 10 и 20 торговых сессий. Контракты и даты не объединяются. При смене срочного
контракта наблюдение за старым прогнозом не переносится на новый контракт.

## Правила, фиксируемые до появления исхода

1. Прогноз берётся из неизменяемой записи, уже сохранённой до исхода. Для каждого
   горизонта используется направление именно из соответствующей строки прогноза.
2. Единственный простой ориентир заранее закреплён: всегда ожидать рост. Он
   сравнивается с моделью на тех же строках с завершённым исходом.
3. Направленная запись считается верной, если цена закрытия точно через N сессий
   выше для прогноза роста или ниже для прогноза снижения. Равное закрытие — ошибка
   направленного прогноза. Это оценка изменения от исходной цены к цене в конце
   горизонта, не оценка того, какое из двух ценовых значений было достигнуто первым.
4. `NEUTRAL` и явный отказ от направления (`ABSTAIN`) не засчитываются как
   направленные ответы. Их число и доля показываются отдельно; так инструмент
   не получает лучший балл за счёт молчаливого исключения неудобных записей.
5. Неполученный исход остаётся ожидающим. Записи с повреждённой связью, неверным
   хешем, повторным ключом, другим рынком/SECID, неправильным горизонтом или
   нарушенным временем закрывают построение сводки целиком.
6. Выводятся число сохранённых прогнозов, число созревших и ожидающих исходов,
   охват направленных решений, число верных ответов каждого правила и разность
   точности в процентных пунктах. Каждая комбинация рынок/SECID/горизонт имеет
   собственную строку; объединённый общий балл не вычисляется.
7. Сохраняются все записи и все отказы. По результатам этой сводки нельзя менять
   пороги, направление, условия допуска или ориентир задним числом.

## Проверки входа и запуск

Перед расчётом проверяются версия и состав таблиц, хеши записи прогноза, квитанции,
исходных байтов, будущих данных и канонической записи исхода. Для однофайловой
DuckDB также проверяется соответствие исхода исходной записи будущих данных по
рынку, SECID, сроку, цене и идентификатору. Проверяются точный `forecast_id`,
горизонт 5/10/20, временной порядок T0 → сохранение → будущие данные → исход,
доходность и её соответствие исходной/конечной цене. База открывается в режиме
только чтения; запись результата, если она нужна, выполняет пользователь отдельно.

Старый SQLite-журнал не сохраняет отдельный полный список будущих свечей.
Для него подтверждается связь с непустыми исходными байтами по контрольной сумме,
согласованность записанной цены, доходности и времени. В DuckDB дополнительно
сверяется полное сохранённое окно будущих свечей с календарём и итоговым исходом.
Сам оценщик не разбирает исходные ответы поставщика заново: это ограничение явно
показано в поле `future_evidence_validation` отчёта для каждого формата.

Пример запуска:

```text
python -m scripts.g2_prospective_baseline_scorecard --ledger <явный-путь-к-опытному-журналу.sqlite3-или-duckdb>
```

Для понятного русского отчёта добавить `--format text`; для сохранения также
указать `--output <путь-к-отчёту.txt>`. По каждому рынку, точному инструменту и
сроку выводятся сохранённые решения, завершённые и ожидающие исходы,
проверенные направленные прогнозы, верные ответы, ошибки и сравнение с правилом
«всегда рост» на той же выборке. Нейтральные решения и явные отказы видны отдельно.
При отсутствии результатов точность обозначается как пока неизвестная;
при отсутствии направленных решений она не рассчитывается. Отказы не исчезают
из общего числа решений. Прежний машинный JSON остаётся форматом по умолчанию.

По умолчанию сводка печатается в окно; необязательный `--output` сохраняет её в
указанный файл. Файл базы не изменяется.
Запись отчёта поверх самой базы, её служебных файлов или другой ссылки на тот же
файл запрещена до расчёта. Несогласованная дата сессии и время её закрытия также
останавливают построение сводки, даже если контрольная сумма была пересчитана.

## Как понимать результат

Разность точности — описательное сравнение на имеющихся одинаковых строках.
Повторные прогнозы и горизонты могут перекрываться, поэтому здесь нет заявлений
о статистической независимости, значимости, доходности, качестве первого касания
или переносимости на будущие рынки. Недостающие исходы, малый объём и широкое
воздержание показываются явно.

Хеши обнаруживают повреждение или несогласованное повторное изменение внутри
файла, но не подтверждают подлинность поставщика, внешних часов или биржевого
календаря. До появления реальных зрелых исходов измеренный результат отсутствует;
эта процедура только закрепляет способ сравнения, не изображая будущий результат.

Оценщик принадлежит отдельному блоку качества. Он только читает форматы журналов,
созданные другими компонентами; сбор данных, квитанции, календарь и устройство
хранилищ остаются ответственностью соответствующих блоков. Никакого изменения
HOME, главной ветки, рабочей базы, записи прогноза или исхода не выполняется.
Допуск выпуска остаётся закрытым.

## Прослеживаемость отдельных решений

Машинный отчёт дополнен observations: одна запись на номер прогноза и срок. Сохранены точный инструмент, направление, время, исходная цена, контрольная сумма прогноза, полученный исход или ожидание, участие в сравнении и причины исключения. Для ожидающих и ненаправленных решений результаты обоих правил остаются NULL. Полученный нейтральный исход сохраняет изменение цены, но не включается в точность. Итоги групп теперь считаются из этих же отдельных записей. Повторный исход на ту же пару отвергается.

Версия V3 сохраняет в каждой отдельной записи дословный список причин явного отказа, если он был записан самим источником прогноза. Общая сводка считает долю направленных строк среди всех строк «прогноз × срок», нейтральные решения, явные отказы, ожидающие и полученные исходы, а также частоту каждого исходного текста причины. Те же итоги и причины отдельно показаны по точному инструменту и каждому сроку 5/10/20; проверяющая программа независимо пересчитывает все уровни сводки из отдельных строк. Причины не выводятся из пропусков данных и не переводятся в догадки. Русский отчёт показывает разбивку, таблица сохраняет дословный текст причины.

`--format text --details` показывает эти записи на русском; обычная краткая сводка сохранена. На шести настоящих сохранённых журналах получены 18 ожидающих строк; файлы остались неизменны. Будущие цены не подставлялись. Три дополнительные проверки подтверждают совпадение подробностей с итогами, неизвестные значения при ожидании и вывод номера/результата без изменения базы.


## Повторяемость и контроль связей

`report_sha256` — SHA-256 канонического JSON всего отчёта без самого поля report_sha256. Текущее время и путь файла не добавляются: одинаковые записи дают одинаковый результат. Контрольная сумма предназначена для сравнения отчётов и не удостоверяет внешнюю подлинность источника. Подробности дополнены capture_receipt_sha256, capture_source_sha256 и outcome_sha256; последний остаётся NULL до появления исхода.

Проверяются повторное открытие и копирование журнала для обоих форматов, перестановка физического порядка строк, изменение суммы при изменении состава завершённых исходов и отказ при повторном исходе одной пары прогноз/срок. Шесть настоящих журналов прочитаны дважды: машинные и подробные русские отчёты совпали, контрольные суммы баз не изменились. Реальные исходы по-прежнему ожидаются.


## Единый блок проверки и выгрузки оценки

Добавлен `scripts/g2_prospective_scorecard_review.py`. Он принимает изолированный журнал или сохранённый машинный отчёт, проверяет его целиком и выдаёт русский текст, машинный документ или таблицу отдельных решений. Программа не пишет в журналы и не получает новые биржевые данные.

Проверка включает контрольную сумму всего документа, известную версию и ограничения, состав/типы полей, уникальность пары прогноз/срок, наличие всех 5/10/20, одинаковую исходную запись для трёх сроков, временной порядок, положительные цены и доходность, результат двух правил, причины исключения и независимый повторный подсчёт всех итоговых чисел из подробностей. Пересчитанная вручную контрольная сумма не позволяет скрыть противоречие между строками и итогами. Только внутренне согласованный документ всё ещё может быть поддельным; `--match-ledger` отдельно сравнивает его с новым чтением указанного журнала, где выполняются проверки исходных записей. Обе проверки не удостоверяют внешний источник, часы или календарь.

Старые отчёты без нынешних подробностей и сумм не дополняются вымышленными данными: их нужно заново построить из исходного журнала. Изменившийся после отчёта журнал вызывает отказ, даже когда сохранённый документ сам по себе согласован. Свежий отчёт можно построить отдельно, не заменяя старый журнал.

### Использование

```powershell
# Проверить журнал и получить краткое заключение
py -3.13 scripts/g2_prospective_scorecard_review.py --ledger pilot.sqlite3 --check-only
# Сохранить полный машинный отчёт
py -3.13 scripts/g2_prospective_scorecard_review.py --ledger pilot.sqlite3 --format json --output scorecard.json
# Проверить сохранённый отчёт и его связь с журналом
py -3.13 scripts/g2_prospective_scorecard_review.py --report scorecard.json --match-ledger pilot.sqlite3 --check-only
# Выгрузить каждое решение в таблицу
py -3.13 scripts/g2_prospective_scorecard_review.py --report scorecard.json --match-ledger pilot.sqlite3 --format csv --output decisions.csv
# Подробный текст после тех же проверок
py -3.13 scripts/g2_prospective_scorecard_review.py --report scorecard.json --match-ledger pilot.sqlite3 --format text --details --output decisions.txt
```

Таблица имеет русские заголовки, разделитель `;`, кодировку UTF-8 с отметкой для Windows. Ожидающие цены и оценки остаются пустыми. Полученные нейтральные исходы/явные отказы сохраняют изменение цены, но не получают направленную оценку. Правило «всегда рост» проверяется на тех же строках, что и прогноз. Текстовые идентификаторы, похожие на формулы, получают начальный апостроф при выгрузке; исходный машинный документ остаётся неизменным. Кавычки, разделители и переносы строк обрабатывает стандартный модуль CSV.

Запись результата запрещена поверх входного отчёта, журнала, его служебных файлов и ссылок на тот же файл. Проверка выполняется до записи: повреждённый документ не уничтожает прежний выходной файл. Повторяющиеся ключи JSON и нечисловые NaN/Infinity отвергаются. Программа запускается по абсолютному пути из другой папки.

### Проверка всего пути

Оба формата журнала проходят сохранение → повторное чтение отчёта → сверку с журналом → выгрузку таблицы. Совместимость с точным writer PR #202 остаётся отдельной проверкой в одноразовом окружении и дополнена проверкой документа и выгрузки. Отрицательные случаи охватывают неверные итоги/доли/типы/сроки/хеши/времена, ложное включение, неправильный знак результата, заполнение ожидающих значений, изменения ограничений, повторные записи, опасные выходные пути и несоответствие журналу. Рост, снижение и отсутствие движения проверены отдельно: нулевое движение не считается успехом направленного прогноза.

На шести настоящих SQLite-журналах сохранено шесть машинных отчётов, каждый заново прочитан и точно сопоставлен со своим журналом. Получены шесть таблиц и общая таблица 18 решений. Все 18 исходов ожидаются; оценки пустые, точность неизвестна. Контрольные суммы шести журналов до/после совпали. Местный комплект `assessment-package-20261011` содержит `six_markets.csv`, `six_markets.json`, `six_markets.txt`, отдельные документы по рынкам и `verification.json`. Общая таблица — объединение этих шести проверенных отчётов, не отдельный новый журнал. Реальные будущие результаты не создавались.


После связанных проверок добавлена общая проверка всех тестов собственной основы и всех тестов точной линии записи PR #202 с подставленными только файлами оценщика. Это временное проверочное окружение; объединение веток и рабочая установка не выполняются.


## Общий запуск нескольких журналов

`scripts/g2_prospective_scorecard_batch.py` принимает несколько `--ledger` и создаёт новый полный комплект в `--output-dir`. Один журнал не допускается дважды, в том числе через ссылки. Один номер прогноза не допускается в нескольких журналах даже с одинаковыми байтами: копия не увеличивает число наблюдений. Разные форматы/версии журнала, версии прогнозной модели и записи не объединяются; неизвестная версия модели тоже закрывает общий подсчёт. Эти две версии взяты из исходного неизменяемого прогноза и сохранены в подробностях. Обычная одиночная оценка допускает явно неизвестную версию модели, но общая оценка её не смешивает.

Итоги пересчитываются из всех отдельных решений, а не усредняются по процентам отдельных журналов. Точные контракты остаются отдельными группами; разница версий модели никогда не скрывается в одном числе. Нейтральные, отказы и ожидания не попадают в знаменатель направленной точности. Порядок входных журналов не влияет на содержание комплекта.

```powershell
py -3.13 scripts/g2_prospective_scorecard_batch.py --ledger SBER.sqlite3 --ledger Si.sqlite3 --ledger BR.sqlite3 --ledger GOLD.sqlite3 --ledger IMOEX.sqlite3 --ledger RTSI.sqlite3 --output-dir result-six
py -3.13 scripts/g2_prospective_scorecard_batch.py --verify-package result-six
```

Папка результата должна быть новой, родительская папка — существующей. Сначала полностью проверяются входы, затем комплект формируется в отдельной временной папке того же родителя. Каждый входной журнал заново читается после построения файлов: изменение данных вызывает отказ до публикации. После проверки содержимого папка переименовывается в результат. Старые папки результата не заменяются. Неопубликованная временная папка удаляется только после проверки, что это созданная нами папка под выбранным родителем. Это согласованный последовательный набор чтений, а не единая транзакция всех независимых журналов: запись коллеги не блокируется и не изменяется.

Комплект содержит `combined.json/csv/txt`, по три файла `journal_NNN` на каждый вход и `manifest.json`. Описание связывает относительные имена отчётов с исходными журналами и содержит контрольные суммы всех файлов. Отдельные записи дополнительно сохраняют версию записи прогноза и версию модели. Повторная проверка проверяет точный состав папки, суммы, отдельные отчёты, заново объединённые итоги и точное соответствие текстов/таблиц отчётам. Даже после замены сумм в описании неверная выгрузка отвергается. Имена файлов формируются программой; путь исходного журнала не используется как имя выходного файла.

Режим `--verify-package` проверяет сохранённый комплект и не читает исходные журналы. Он не доказывает подлинность источника или последнюю актуальность журнала. Старые одиночные документы без версий в подробностях нужно перестроить из журнала для этой версии проверки.

Настоящий запуск: `batch-six-markets-20261011`, шесть журналов, 22 файла, 18 отдельных решений, 15 направленных и 3 нейтральных. Все 18 исходов ожидаются, оценки пустые. Контрольные суммы шести исходных копий совпали с предыдущим подтверждением сохранности; отдельное свидетельство `batch-six-markets-evidence-20261011.json` находится вне проверяемого комплекта. Новых биржевых запросов и записи исходов не было. Первая и повторная проверки комплекта успешны.


## Сравнение двух комплектов во времени

`scripts/g2_prospective_scorecard_changes.py` сравнивает два полных сохранённых комплекта. Каждый комплект сначала полностью проверяется, после построения сравнения проверяется снова. Исходные журналы заново не открываются. Старый набор должен целиком присутствовать в новом: исчезновение прогноза закрывает сравнение. Все исходные поля старого прогноза, включая направление, точный инструмент, версии, время, цену и связи с исходными записями, должны остаться прежними. Полученный исход не может измениться или вернуться в ожидание. Допускаются новые номера прогнозов и переход прежнего ожидания в полученный исход.

Отдельно показываются новые прогнозы, новые исходы прежних прогнозов, неизменные прежние ожидания и исходы, текущий остаток ожиданий и показатели до/после по рынку, точному инструменту и сроку. Разница точности вычисляется только при наличии завершённых направленных оценок в обоих комплектах. Иначе она остаётся NULL. Полученный нейтральный исход сохраняется, но не включается в точность. Новые прогнозы могут изменять состав наблюдений: изменение общей точности не доказывает улучшение модели. Последовательность дополнения проверяется по записям; глобальная хронология и подлинность внешнего источника не заявляются.

```powershell
py -3.13 -X utf8 scripts/g2_prospective_scorecard_changes.py --before prior-package --after current-package --output changes.txt
py -3.13 -X utf8 scripts/g2_prospective_scorecard_changes.py --before prior-package --after current-package --format json --output changes.json
```

Выходной файл должен быть новым и находиться вне обоих исходных комплектов. Внутри комплектов ничего не дописывается; существующий результат не заменяется. Машинный вывод содержит суммы обоих отчётов/комплектов и сумму всего сравнения.

Настоящая проверка: сохранённый batch-six-markets-20261011 сопоставлен с заново построенным batch-six-markets-repeat-20261011 из тех же шести неизменных журналов. Новых прогнозов и исходов нет, все 18 ожиданий сохранены; изменения количеств равны нулю, изменения точности неизвестны. Получены changes-real-six-20261011.json/txt. Контрольные суммы всех шести журналов остались прежними. Появление новых исходов проверяется на искусственных данных и не выдаётся за реальные будущие результаты.


## Разбивка охвата по рынкам и срокам

Отчёт V3 дополнительно группирует те же сохранённые строки по точному инструменту и по сроку 5/10/20 сессий. Каждая разбивка отдельно показывает направленные/нейтральные/отказные решения, ожидающие/полученные исходы и долю направлений. Исходные причины явного отказа подсчитываются отдельно внутри каждой группы. Эти числа дают ответ, где именно встречается сохранённая причина, но не объясняют её сверх текста, записанного движком.

Проверяющий блок заново строит обе разбивки из наблюдений. Испытания меняют число в общей сводке, отдельной группе инструмента и группе срока, а также проверяют частоту одного искусственного текста причины в каждой группе. Пакет нескольких журналов строит общую разбивку после объединения исходных строк; проценты по журналам не усредняются.
