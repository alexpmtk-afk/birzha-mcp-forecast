## Установленные причины
1. HKCU/Software/Microsoft/Windows/CurrentVersion/Run, ChatGPT-Birzha-HistoryRefresh запускает %LOCALAPPDATA%/ChatGPT-PK/BirzhaControl/run-history-refresh.ps1 с корнем C:/ProgramData/ChatGPT-PK/BirzhaControlQueue. Это отдельная копия, а не файл внутри HOME git checkout. Сохранённые bootstrap-birzha-control.ps1 в C:/ProgramData/ChatGPT-PK/BirzhaControlStage/* устанавливают её копированием из stage и регистрируют этот Run key. Точная историческая стадия установки текущих байтов не доказана; позже копия менялась. Обновление git checkout само по себе её не обновляет.
2. В установленной копии два действующих набора содержат RTSI: history.sync_batch и цикл mirror.sync. В старом HOME session_data_rules.py и google_sheets_bridge.py также направляют индекс RTSI в ту же книгу, которая теперь принадлежит RI. Это ошибка активной версии, а не повод менять исторические архивы. Новый main исключает эту маршрутизацию. Полного аудита неизвестных внешних сценариев не заявляем.
3. MCP-Birzha-HOME в Task Scheduler — запуск приложения при входе пользователя, а не расписание D1. Часовой цикл живёт в отдельном сценарии с интервалом 3600 секунд. Во время проверки отдельный процесс цикла не подтверждён; лог доказывает предыдущие запуски, не текущее выполнение.
4. C:/MCP-HOME/runtime/birzha/native-mirror-config.json отсутствует. pending.json имеет enabled=false, sole_writer=false и отложенное включение из-за других писателей. start-birzha-home.ps1 по умолчанию отключает нативное зеркало; mirror.sync при отсутствии конфигурации возвращает BLOCKED. Это подтверждено кодом/файлами/журналом, не новым живым mirror.status. Аудиторский gateway недоступен, прямой MCP требует авторизации; значения секретов не читались.
5. В новом main RI mirror.sync вызывает archive.update, возвращающий MODEL3_ARCHIVE_READBACK_PASS, written=true. Старый часовой сценарий принимает только MIRROR_SYNC_PASS. После простого обновления он мог бы сообщить ошибку уже после успешной записи RI. Для остальных пяти инструментов MIRROR_SYNC_PASS не содержит written: нужно проверять их собственный контракт, а не навязывать поле RI.
6. Запуск скрипта прямо из repo ранее искал birzha_mcp_client.py рядом с собой, хотя помощник находится во внешней установленной папке. Добавлен явный параметр McpHelperPath и правильный локальный путь по умолчанию.

Успехи RI и остальных инструментов проверяются по разным реальным контрактам. Неуспешный или пробный результат RI не принимается за применённую запись. Тексты произвольных исключений в журнал цикла больше не выводятся. Mutex переведён в Global для исключения двух новых циклов в разных сеансах; старое поколение с Local надо отдельно завершить в разрешённое окно. Источник SHA для логов — не свидетельство фактической свечи.
