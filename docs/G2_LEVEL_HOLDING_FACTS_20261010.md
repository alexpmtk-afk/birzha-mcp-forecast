# G2 — последовательные закрытия и полнота окна

Основа #157 abe9a42ddf1242e30162c51bfd6207127c34e92a. E08 требует причинного
окна; полная модель силы удержания не принята. Новый отдельный блок не меняет
прогноз, исходные реакции, Outcome или production.

## Реализовано

Для девяти прежних уровней: серии закрытий ABOVE/ON/BELOW, максимальная
длина по каждой стороне, последняя серия, первый/последний момент закрытия
и прошедшее между ними время. Число свечей, весь диапазон которых выше/ниже
уровня, хранится отдельно. ON прерывает серию ABOVE/BELOW.
Прошедшее время между закрытиями не является временем непрерывного пребывания
цены на стороне уровня, в том числе при ночном/выходном перерыве.
Сила/Control остаются UNKNOWN, continuous_price_dwell_seconds=NULL.

Расписание ожидаемых свечей передаётся отдельно и не восстанавливается
построителем из имеющихся цен. Код проверяет полноту относительно этого
объявленного внешнего расписания; подлинность и независимую полноту источника
расписания обязан проверять вызывающий контур. Метка EXTERNAL_EXPECTED_SCHEDULE
сама по себе не удостоверяет биржу или календарь.

Согласованы символ, точный SECID, период, границы окна и время получения
расписания не позже наблюдения. Свечи проверяются прежним причинным валидатором
реакции. Дневная полнота сопоставляется по московской дате торговой сессии,
как существующий sequence_quality: MOEX end отражает последнюю сделку и может
отличаться от границы расписания. H1/M15 требуют точных begin/end. Дубли
дневной сессии запрещены. Пропуск или лишняя свеча закрывает ВСЕ показатели
серий этого окна; отсутствующее расписание не означает доказанную непрерывность.
Нет наблюдений -> NULL, известное отсутствие серии на стороне -> 0.

## Внешнее расписание

Отдельный JSON-файл: version EXPECTED_BAR_SCHEDULE_V1, origin
EXTERNAL_EXPECTED_SCHEDULE, complete=true, symbol, secid, timeframe, source,
observed_at (явный часовой пояс), window_start/window_end и expected_bars
(упорядоченные пары begin/end). Байты сохраняются по SHA256 в отчёте. Весь
файл ограничен 5000 ожидаемыми свечами; повторяющиеся поля JSON запрещены.
Объявленное окно должно начинаться не раньше фиксации уровней и завершаться
не позже observation_at. Если расписание отсутствует, отчёт показывает
EXPECTED_SCHEDULE_MISSING и недоступные показатели, без выдуманного календаря.

```powershell
python scripts/g2_level_holding.py --forecast forecast.json --candles candles.json --schedule schedule.json --observation-at 2026-03-02T14:00:00+03:00 --journal holding.sqlite3 --format text
```

Без --journal команда только читает и выводит результат. Отдельный SQLite
журнал связывает неизменяемый прогноз/свечи/расписание/момент наблюдения:
повтор идемпотентен, новый момент добавляется, подмена forecast_id запрещена,
повреждение сохранённых байтов выявляется при чтении. Исходные файлы не
перезаписываются. Есть понятный русский отчёт и машинная форма.

Это фактологический слой, не принятая шкала силы удержания и не доказательство
готовности боевой установки. Реальное расписание и источники отдельно не
принимались. Совместимость проверяется поверх точной зависимой основы.
