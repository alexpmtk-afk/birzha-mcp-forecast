# G2 — общий алгоритм объединения факторов для прогнозирования (исследовательский контракт V1)

Дата: 17.10.2026. Назначение: устранить пробел между 72 блоками вкладки «Прогноз — механика» и реальным итоговым алгоритмом. Это отдельная ограниченная исследовательская реализация, не изменение Protocol 08, не одобренные веса, не торговая стратегия и не разрешение на HOME/merge/deploy.

## Принцип: все значимые факторы рассматриваются в одном процессе, но не все становятся голосами

1. **Admission / Causality**: Instrument/exact SECID; source payload SHA; event_end, observed_at, T0; календарь, завершённость, версии, применимость, недостающие данные. Восстановленная история = RECONSTRUCTED_RESEARCH_ONLY. PROSPECTIVE_RECEIPT_RESEARCH требует event_end, observed_at, source SHA, но само заявление входных метаданных **не является независимой аттестацией поставщика**. Не подменять отсутствие данными из будущего.
2. **Factor producers**: существующие P/V/E-блоки, единые T0/исходный snapshot, точные формулы и версии. Не менять источники ради модели. Простые v0.4/v0.6 используются как **отдельные контрольные методы**, не как два независимых голоса.
3. **Family mapping**:
   - PRICE: E02 / State (D5/D20/ER/W20; HH/HL допускается только после отдельной версии/проверки).
   - FLOW: E06 Pressure + E09 Effort→Result (общая группа, не два независимых голоса).
   - REACTION: E10 Control/Holding — отдельная группа, но потенциальная зависимость от цены/потока остаётся в предупреждениях.
   - ROUTE E12 — обязательное условие одной из моделей, не ещё один «независимый» голос.
   - LOCATION E05, EFFICIENCY P06, VOLATILITY P03/P04/P09 — контекст или veto/gating. Сам по себе беззнаковый ER, ATR или профиль не может голосовать за UP/DOWN.
   - S01 Alignment15 из PR #203/#204 — **другой экспериментальный кандидат**; не смешивать его предварительные баллы с probability и не складывать с факторными голосами.
4. **Factor evidence contract**: family, status, signed_strength [-1,+1] *только от направленного версионированного producer*, event_end, observed_at, source_sha256. Обязательно сохранять status: AVAILABLE / UNAVAILABLE / INSUFFICIENT_HISTORY / NOT_APPLICABLE / DEGRADED / PROXY. Нельзя превращать пропуск, proxy Volume Profile или недоказанную классификацию в ноль или уверенное направление.
5. **Candidate combination rules**: код `g2_factor_fusion_research.py` сравнивает три заранее зафиксированные инженерные гипотезы без подбора весов на контрольной выборке:
   - GROUP_MAJORITY: согласованность как минимум двух направленных групп (2/3 присутствующих голосов).
   - GROUP_MEAN: средний знаковый сигнал групп >=0.45 по абсолютной величине, поддержка >=2 и отсутствие сильного противоположного сигнала.
   - STATE_CONTROL_ROUTE_CONSENSUS: совместное направление состояния, контроля и маршрута (минимум |0.4| у каждого); сильное противоположное давление — veto.
   - DEGRADED volatility — veto всех направленных кандидатов.
   - Результат = **candidate_direction / ABSTAIN**, никогда не команда на сделку, не значение вероятности и не утверждение о статистическом преимуществе.
6. **Coverage versus accuracy**: цель — повышать качество среди честно охваченных прогнозов, но одновременно показывать долю отказов; нельзя получить «100% точности», оставив один удобный случай. Отчёт по каждому рынку/режиму/горизонту.
7. **Freeze + Outcome**: код/порог/manifest/evidence hash фиксируются до будущих исходов. Любой исход дописывается отдельно к неизменному Forecast. Текущий модуль не пишет в ForecastJournal, OutcomeJournal и production DB и не зарегистрирован как MCP-инструмент.

## Минимальная схема проверки нескольких алгоритмов

- A: плоская цена (unchanged-price baseline).
- B: инерция последних пяти завершённых D1 (5D momentum).
- C: исходный v0.4, отдельно v0.6, на точно одинаковых T0/инструментах; совместное голосование v0.4+v0.6 **не считаем независимым**.
- D/E/F: три варианта объединения из этого модуля.
- G: Alignment15 PR #203/#204 только после подтверждённой совместимости и исправления известного ретроспективного выбора уровней; сравнивать, а не объявлять одобренным.
- На первых шагах: пригодная реконструированная выборка только для *Development*. Заблокировать заявления об OOS и реальной ex-ante точности без фактического first-receipt, независимого untouched периода или накопленных вперёд наблюдений.
- Исходы: направленное движение, UP_FIRST/DOWN_FIRST/NEITHER/AMBIGUOUS, ошибка величины (MAE), MFE/MAE, time-to-hit, coverage, abstention, число наблюдений и неопределённость по 5/10/20 сессиям.
- Разделять calibration/discovery/future tests по времени; исключать утечку при пересечении label windows (purge/embargo до 20 сессий согласно эксперименту). Не использовать random shuffle и не проверять множество комбинаций на том же финальном holdout.
- Регистрировать **все** попытки и неудачи; при изменении порога — новый experiment_id/версия, новый нетронутый контроль. Сравнение с v0.4/v0.6 должно иметь одинаковые T0/покрытие; дополнительно показывать coverage-adjusted metrics. Минимум статистических наблюдений определять до финальной приёмки, не объявлять проценты по 17 исходам доказательством преимущества.

## Что в текущем PR реализовано

- Один чистый, без побочных эффектов **комбинатор предрассчитанных доказательств**, а не новый producer и не доступ к MOEX.
- Валидатор времени/статусов, запрет дублирования семей, отсутствие вероятностей и operational signal, хеш конкретного входа, три предзарегистрированные схемы, причины воздержания и синтетические тесты.
- Отсутствуют: адаптеры истинных PR #200/#204/#259, реальная прогонка на исходных данных/сохранённых snapshots, проверка полной lineage correlation, показатели эффективности, независимая проверка и одобренные веса.

### Критерий технического PASS этого ограниченного этапа

Тесты на корректный согласованный сигнал, противоположные доказательства, пропуски, дублирование, unsigned factors, время после T0, proxy и degraded данные, сохранение детерминизма проходят; CI на SHA новой ветки успешен. Это **не** PASS прогнозной точности, исходных данных, OOS или полного Protocol 08.
