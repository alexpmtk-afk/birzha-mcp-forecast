# Импорт кластеров RI из SBProX 8 за 2026 год

SBProX поставляет минутные агрегаты по цене. Канонический архив свечей RI в Google
и существующий сборщик MOEX остаются независимым эталоном. Этот импортёр читает
вручную полученные локальные файлы; он не управляет SBProX и не регистрирует команды
на работающем MCP. Источник не даёт реестра сделок, снимков стакана, надёжного OI
или времени публикации данных в прошлом.

## Вход и подготовка

- Источник Windows — C:\SBProData\local_cachedata\v1.7\bars\rsRTS\Auto_True\60\10\Russian Standard Time.
  Имена — YYYY-MM-DD.locchache. Диалект ASCII, разделители : * |, CRLF допустим.
  Порядок цен в кэше — максимум, минимум, открытие, закрытие. Цены — целые пункты
  котировки RI; объёмы — контракты. Сохраняются исходные числовые поля как строки.
- Серия берётся из каждой минуты. Соответствие 03-26/06-26/09-26/12-26/03-27
  означает RIH6/RIM6/RIU6/RIZ6/RIH7 и проверяется по срокам из CONTRACTS.
  Режим Auto не доказывает наличие всех параллельных серий.
- Рабочая локальная папка должна находиться вне кэша и вне автоматически
  синхронизируемых папок. Для сверки требуется папка с выписками JSONL: contracts
  (SECID, начало, конец), sessions (SECID, календарная дата, тип строки, тип расписания,
  начало вечера, торговая дата дня, торговая дата вечера, качество), pilot_h1
  (строки A:M из H1 для RIH6 11.02.2026 без заголовка). Все прочие выписки содержат
  строку заголовка. Для сверки ZIP добавить m1_index (A:K из M1_SOURCE_INDEX)
  и указать существующую папку 01_M1_SOURCE. Выписки не включать в Git.
- Запуск из изолированного клона: с PYTHONPATH=src вызвать
  python -m birzha.application.sbprox_archive --source PATH --output PATH
  --reference PATH --through YYYY-MM-DD [--start YYYY-MM-DD] [--moex-dir PATH].
  Верхняя граница строго до текущей календарной даты Москвы. Неизвестные сессии
  остаются неизвестными. Незакрытый кусок биржевой даты у границы помечен как
  наблюдаемый и неполный.
- По каждой минуте и каждому уровню проверяются volume = Ask + Bid,
  Delta = Ask − Bid, OHLC и сумма уровней. Минутный ключ — точный SECID и начало
  минуты, ключ уровня дополнен ценой. Повторный ключ, неизвестная серия,
  изменённый во время чтения или неизвестный формат изолируют файл целиком.
  Нулевой файл сохраняется в инвентаре. Ноль байт не означает нулевой объём.
  Неторговый день отмечается только при закрытом рыночном календаре без
  наблюдаемых точных контрактов. Известная торгованная дата без файла —
  TRADING_DAY_MISSING_DATA. При отсутствии доказательств остаётся UNVERIFIED.
- Правила SESSIONS раздельно определяют календарную и торговую даты.
  Точность этой классификации наследует качество исходной строки, включая
  SPLIT_TRADE_DATE_BY_PHASE_NOT_ISS_ATTESTED. Периоды H1/M15 — по Москве, D1
  сравнивается по торговой дате. Различие D1 может возникнуть из-за границы
  сессии или другого биржевого правила. Сама сверка не устанавливает причину.

## Хранение, повтор и проверка

Одна логическая коллекция RI_SBPROX_2026. Результат — локальное неизменяемое
поколение с идентификатором по версии алгоритма, входам и выпискам. Подготовленные
дни повторно используются после проверки контрольных сумм. Готовое поколение
сохраняет исходные байты в RAW, разделы NORMALIZED/M1_BARS и PRICE_LEVELS в
Parquet/ZSTD по SECID и календарному месяцу, расчёты в DERIVED, проверки в REPORTS
и manifest.json с SHA-256. Публикация локального поколения — переименование
временной папки после проверок. Изменившийся файл образует другое поколение.
Старые поколения сохраняются и автоматически не назначаются активными.
Повтор того же входа проверяет все хеши и возвращает UNCHANGED.

Отчёт сравнения хранит точный SECID, окно, значения обеих сторон, SHA эталонного
ZIP и MATCH/MISMATCH/MISSING/UNVERIFIED. Источники не исправляются по итогам
сравнения. На рынках с пересекающимися сериями MISSING описывает отсутствие
конкретного ключа SBProX относительно архива, а не обязанность режима Auto
собрать вторую серию.

## Показатели и границы применимости

- FLOW сохраняет M1, M15, H1 и доступные торговые сессии. Накопленная дельта
  сбрасывается по SECID и торговой дате. Для неизвестной сессии она пуста.
  Выборка по пользовательскому окну сбрасывает накопление на начале окна.
- Читающий адаптер SBProXResearchReader отдаёт покрытие, объём по цене, POC,
  VAH/VAL, HVN/LVN, миграцию профиля, footprint, диагональный дисбаланс по явно
  заданным шагу и коэффициенту и пару объём/изменение цены. Строки после момента
  запроса исключаются; неполная минута исключается. Доступность на исторический
  T0 неизвестна. Импортный first_seen — время локальной подготовки.
- Исследовательское правило V1: 70% Value Area расширяется к соседнему
  наблюдаемому уровню с большим объёмом, при равенстве берётся меньшая цена.
  Для POC при равенстве выбирается меньшая цена. HVN/LVN — строгие локальные
  экстремумы по соседним наблюдаемым уровням. Результат не утверждает, что
  Пурнов использует именно эти параметры. Диагональное сравнение требует двух
  существующих уровней и положительного знаменателя.
- Для 87 правил Пурнова предлагается добавить отдельное покрытие
  OBSERVED_RESEARCH_ONLY только для кластерного объёма, наблюдаемой Bid/Ask Delta,
  профиля и производных от них. Старые APPROX и p3_minute_sign_delta_proxy
  сохраняют прежнюю семантику. OI, FUTOI, реестр сделок, состояние стакана и
  историческая доступность остаются отдельными источниками или пробелами.

Действующее место хранения — существующая папка 03_SBPROX_HISTORY_2026 книги RI.
По решению владельца исходники и все исходные колонки объединены в один
RI_SBPROX_2026_MASTER.zip: RAW, TABLES, DERIVED, REPORTS, PROVENANCE и MANIFEST.json.
Публикация этого файла уже разрешена владельцем и выполнена отдельной операцией;
это не разрешение на изменение основной Google-книги или установку на HOME.
При следующем обновлении сохранять ID файла и проверять контрольную сумму
обратным чтением. Изменения STORAGE_RULES, журналов и HOME проходят отдельно.

## Действующая цепочка MCP и последующий перенос в книгу

Источник архива закреплён по ID 1tjN9bHtmXHSbteD3TBCX_eiyOyz7eDwu в папке
1DMI1dZdYomr9Jm31EHrHb9Qiux5de9oT. Новые локальные даты владелец открывает в SBProX.
Импортёр сопоставляет файлы с реестром и хешами, проверяет контракт каждой минуты
и создаёт проверенное локальное поколение. Повтор с теми же файлами возвращает
UNCHANGED. Изменённый старый файл требует разбора конфликта.
Упаковка поколения в MASTER и публикация на Drive пока являются отдельной
операцией сопровождения: импортёр и новые читающие команды сами файл Drive
не обновляют. Эта операция должна сохранять прежний ID, все исходные поля
и подтверждать публикацию обратным чтением и сравнением SHA-256.
Таким образом, получение исходников вручную, автоматизированный локальный
импорт, публикация файла и чтение MCP — четыре явно разделённых этапа;
сквозное автоматическое расписание этой версией не реализовано.

В существующий archive_server добавлены три читающие команды и одна команда
контролируемого дозаполнения с предварительным просмотром по умолчанию.

| Команда | Назначение |
| --- | --- |
| archive.sbprox_contract | Точный источник, поля, способ получения новых файлов и ограничения |
| archive.sbprox_features | Расчёт M15/H1/D1 по точному SECID из опубликованного ZIP |
| archive.sbprox_sheet_plan | Сверка с существующими свечами и план пустых ячеек текущих листов показателей |
| archive.sbprox_repair_fields | Тот же план, max_cells=1..200; отдельное явно разрешённое применение через общий механизм записи |

Пример параметров features/plan — exact_secid=RIH6, timeframe=H1,
start=2026-02-11T00:00:00+03:00, end=2026-02-12T00:00:00+03:00.
Максимальный запрос — семь суток. Конец исключающий, незавершённая минута
отбрасывается, будущее относительно времени сервера запрещено. Все команды
ограничены RI 2026. Исходные bytes кэшируются в памяти по версии Google,
неизменная версия повторно не скачивается. Для чтения Parquet используются
временные файлы с автоматическим удалением и DuckDB в памяти.

При каждом обновлении версии проверяются закреплённые имя, папка, тип файла,
размер, версия до/после получения и SHA-256 Google. Внутри ZIP проверяются
манифест, хеши обеих таблиц, количество и уникальность временных ключей.
Расчёт не смешивает объёмы разных SECID. H1/M15 агрегируются по московским
часовым границам. D1 использует trade_session_date и наследует её ограничения.
Дневная группа из выбранного окна возвращается с пометкой непроверенной полноты.

В книге RI проверены 95 колонок H1_INDICATORS. Для SBProX предложены отдельные
sbprox_volume_contracts, sbprox_ask_contracts, sbprox_bid_contracts,
sbprox_delta_contracts, sbprox_poc, sbprox_val70, sbprox_vah70, sbprox_hvn_json,
sbprox_lvn_json, sbprox_source_sha256, sbprox_quality, sbprox_formula_version.
Назначение — существующие M15_INDICATORS/H1_INDICATORS/D1_INDICATORS.
Это предложение схемы из 12 дополнительных колонок, а не уже изменённая книга.

План сначала читает книгу, затем источник. Он требует единственную исходную
свечу и единственную строку показателей по точному контракту и времени,
совпадение OHLCV, полное проверенное окно и наличие согласованных колонок.
Заполненные поля исключены из списка обновлений. Хеши исходной строки, целевой
строки, архива и всего плана позволяют привязать последующую приёмку к версии.
Текущий вызов всегда возвращает written=false.

Для Apply реализован sbprox_field_repair: он использует существующие
model3_write_cells, writer_guard и журналы QUALITY_AUDIT/SYNC_STATUS.
Доступ к Apply требует приёмки нового отображения полей и схемы. Перед каждой записью перечитываются пустые ячейки
и контрольные суммы строк, фиксируется PREPARED; затем выполняются точечная
запись и обратное чтение, после которых фиксируется COMMITTED. При потере
ответа повтор начинается со сверки фактических ячеек и журнала. Автоматическая
запись, изменение схемы и расписание этой версией не включаются.

Открытый интерес и счётчик сделок остаются исходными неподтверждёнными полями.
Для их включения нужны отдельная расшифровка и независимая сверка. Существующие
приближённые p3_* сохраняют исходный смысл. Кандидат проходит отдельную установку
на HOME 18085; Forecast 18082 не является сборщиком этого источника.


## Контролируемое дозаполнение — реализация 10.11.2026

archive.sbprox_repair_fields по умолчанию dry_run=true: не пишет даже в журнал.
План содержит выбранные координаты ячеек, их значения, число оставшихся ячеек,
контрольную сумму всего плана и required_schema_sha256. Схема-кандидат строго
состоит из прежних 95 колонок и 12 sbprox_* в указанном выше порядке: 107 всего.
Команда не добавляет колонки, не расширяет сетку и не перемещает строки.
В текущей книге с 95 колонками предварительный просмотр сообщает отсутствие
новых колонок; применение блокируется. Поддержка схемы в коде не означает
согласования её изменения в рабочей книге.

Применение требует dry_run=false, sole_writer на сервере, owner_confirmed=true,
external_writer_exclusion_confirmed=true, expected_plan_sha256 из проверенного
плана и approved_schema_sha256, равного required_schema_sha256. Все подтверждения
относятся к конкретному выполнению; старое окно без чужих правок не считается
бессрочным. Первая проба использует max_cells=1 и не запускается разработчиком
при изолированном тестировании.

Перед записью повторно вычисляется план, читаются весь целевой лист и исходные
свечи, проверяются версия архива, идентичность источника строки, завершённость
и точные границы свечи. Если заполненное поле SBProX или его происхождение
расходятся с расчётом, вся строка исключается, без замены значения. Частично
заполненная строка продолжается только при совпадении ранее сохранённых полей.

В QUALITY_AUDIT фиксируются STARTED, PREPARED, COMMITTED либо ERROR.
PREPARED содержит хеши листа до/после, источника, схемы, плана и координаты,
но не секреты. После PREPARED заново читаются лист, свечи и архив. Запись —
только updateCells с fields=userEnteredValue в пустых колонках 96–107.
Обратное чтение сравнивает весь лист с ожидаемым состоянием, включая прежние
95 колонок и строки 2025 года. Лишь после совпадения фиксируется COMMITTED
и обновляется существующий SYNC_STATUS.

Неизвестный результат не повторяется автоматически. Общий механизм recover
сначала проверяет незакрытые PREPARED, в том числе от старого механизма Модели 3.
Если лист совпал с ожидаемым результатом, фиксируется RECOVERED_COMMITTED,
без новой записи. Если результат ещё не виден или появилась чужая правка,
выполнение блокируется для разбора; старые значения не восстанавливаются поверх
чужих изменений. Межпроцессная блокировка действует на одном компьютере и
не исключает стороннего редактора Google. Поэтому окно без внешних правок
остаётся обязательным условием реального применения, а не свойством тестов.

Существующие coverage/readiness, дозаполнение p3_* и добавление строк поддерживают
оба точных заголовка. В расширенной схеме прежние расчёты затрагивают только
прежние 95 колонок; новые строки получают пустые sbprox_*, без выдуманных значений.
Сама схема, HOME и Google-данные в ходе разработки не изменялись.

Дневные группы по-прежнему не допускаются к записи без подтверждения полноты
торговой сессии. Строго неполные внутридневные окна и неизвестные OI/число сделок
не заполняются. Пригодность исторического источника на момент прогноза не доказана.

## Разреженные торговые часы

Для завершённого H1 или M15 меньшее число минут само по себе не блокирует
запись. Если запрошено целое окно, сверяем SBProX с уже сохранённым ZIP MOEX
из M1_SOURCE_INDEX по точному контракту. Должны совпасть все отметки времени
и OHLCV каждой наблюдаемой минуты. Нулевые минуты не добавляются. Для таких
окон используется статус MATCHED_INDEXED_MOEX_M1_RESEARCH. Идентификатор и
SHA-256 архива MOEX входят в план и квитанцию, перед записью сверяются с
текущим индексом и метаданными файла. Обычные проверки существующей свечи,
границ окна и пустой целевой ячейки сохраняются. Неполные исходные свечи и
D1 требуют отдельного подтверждения. Совпадение наблюдений не доказывает
историческую доступность для прогноза.

## Час с нестандартным окончанием в исходной выгрузке

Для H1 допускаются исследовательские поля SBProX при исходной отметке
неполной свечи, если совпали все минуты двух архивов и сохранённая запись
H1 из того же индексированного ZIP подтверждает контракт, цены, объём,
хеш и точные начало и конец существующей свечи. Последняя наблюдаемая
минута не может начинаться после её конца. Значения записываются со статусом
MATCHED_NONSTANDARD_MOEX_H1_RESEARCH. Время, исходный флаг и старые значения
свечи не меняются. Эта отметка не подтверждает полную сессию и не допускает
наблюдения к прогнозу. Без архивного подтверждения правило не применяется.
