# Приёмка и состояние
Каждому обязательному требованию сопоставить артефакт и независимую проверку. Проверять значения, идентичность, периоды, ключи, дубли, единицы, версии, пропуски, формулы и чтение после записи. Имя файла, статус и HTTP 200 не доказательства. При потерянном подтверждении записи сначала сверить уже записанное.
Разделять локальные тесты, GitHub CI, реальный источник, установленную среду и точность прогноза.

## Вход scripts/control_gate.py
JSON: enabled, paused, initial_request, new_completed_result, all_requirements_verified, blocker_requires_owner — bool; cycle_id — непустая строка; consecutive_no_progress — целое >=0; pending_request — object/null; evidence_refs — список непустых строк; replan — null или объект с непустыми changed_factor, hypothesis, bounded_test, expected_evidence, for_cycle.
Подтверждённая отправка без ID или неизвестная доставка остаётся pending_request до сверки. Вход скрипта — проекция состояния; не заменять им существующий файл координации.
Приоритет: PAUSED → WAIT → START_REVIEW для корректного первого запроса → NO_NEW_RESULT при отсутствии ответа и актуальной переоценки → BLOCKED → COMPLETE с доказательствами → REPLAN → REVIEW.
Скрипт читает и ничего не отправляет/изменяет. Проверяет структуру и условия, а не истинность ссылок. Не подключён автоматически к инструменту отправки: обязательный вызов задан навыком. Не выдавать это за непреодолимую техническую защиту.

## Уточнения переходов после независимой проверки
initial_request — обязательный bool, true только для первого разрешённого поручения, при отсутствии предыдущего результата/неудач. cycle_id — непустой идентификатор текущего содержательного цикла. START_REVIEW разрешает подготовку первого поручения, не автоматическую отправку.
replan дополнительно содержит for_cycle равный текущему cycle_id. Старый план не разрешает продолжить новый безрезультатный цикл. Изменять cycle_id при новом содержательном результате, не при пустом опросе.
Получив новый завершённый ответ, сначала сопоставить его с ожидающим маркером и отправкой. Только после подтверждённого соответствия сохранить принятый ID, снять pending_request и установить new_completed_result=true. Несвязанный ответ не снимает ожидание.
Снятие внешнего блокера без нового ответа: записать reassessment с непустыми for_cycle (текущий cycle_id), evidence_ref (проверка устранения) и reason. Это допускает повторную оценку при отсутствии pending_request, но не обходит паузу, полномочия, блокер или требование нового плана. Не подделывать initial_request/new_completed_result. Отсутствующее reassessment/replan означает null.
Нулевой код завершения означает только успешное вычисление решения. Всегда читать decision. Доказательства должны покрывать каждый обязательный пункт матрицы; скрипт их истинность не проверяет.
