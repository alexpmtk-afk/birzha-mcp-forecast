# Диагностика
Для отказа собрать: безопасные параметры операции, код/SHA, среда, время, число попыток, стадия отказа, полный безопасный текст ошибки, статус/размер ответа, исходный ответ и созданные записи. Не перекладывать доступное исследование на владельца.
Разделять разрешение имени, соединение, ответ, успешный пустой результат, разбор, запись и обратное чтение. Сетевой отказ не означает отсутствие истории. Не обходить запрет доступа сменой среды.

Для каждой гипотезы: предположение → ограниченный различающий опыт → возможные результаты → действие для каждого результата. Использовать работающий аналог после проверки применимости рынка, контракта и единиц.
Первый полезный опыт — минимальный разрешённый участок получения, сохранения и обратной проверки. При аудите без разрешения записи ограничиться чтением. Сохранённые исходники повторно не скачивать. Доступные свечи не задерживать ради всех расширенных показателей.

При установлении причины менять один существенный фактор. Рабочую альтернативу после проверки использовать до полного объяснения старого отказа, если это разрешено.
Проверенное исправление требует воспроизведения отказа, точного изменения, успешного прогона и реального артефакта. Успех в другой среде не доказывает успех у коллеги: передать зависимости и малый приёмочный прогон. Если среда доступна только коллеге — диагностическое поручение, затем независимая приёмка.

После двух безрезультатных циклов сравнить рабочий аналог/среду/параметры или выбрать другую разрешённую гипотезу. Увеличение тайм-аута обосновать и ограничить. При внешнем блокере сообщить факты и минимальное необходимое действие владельца.
